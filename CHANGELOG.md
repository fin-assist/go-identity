# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии и выпуск — [docs/releasing.md](docs/releasing.md). Каждый PR библиотеки, включая документацию, тесты и CI, добавляет строку в «Unreleased»; исключение — полностью ботские PR Renovate только с зависимостями, их сводку по `go.mod` добавляет PR выпуска. При выпуске раздел получает номер версии и дату.

## [Unreleased]

### Несовместимо

- FIN-293: недоступность ключей проверки (нет свежего снимка JWKS пользователя или кластера) больше не выдаётся за невалидный токен: `VerifyUser`, `VerifyService`, `Server` и HTTP-middleware возвращают голый `UNAVAILABLE` без `ErrorInfo` вместо `INVALID_TOKEN` / голого `UNAUTHENTICATED`, отменённый или истёкший контекст — голый `CANCELED` / `DEADLINE_EXCEEDED`. Сбой `user` или API-сервера больше не разлогинивает клиентов. Сервисам код менять не нужно: `bank-bff` отвечает на неизвестную `finerr.ToREST` ошибку 500 `INTERNAL_ERROR`; если сервис сам сравнивает ошибку `VerifyUser` с `INVALID_TOKEN`, учтите новые коды. Метрика `finassist_identity_rejected_total` получила причину `unknown_key` (неизвестный `kid` в свежем снимке, раньше считался как `key_unavailable`); `key_unavailable` теперь только сбой источника ключей.

### Добавлено

- FIN-273: `NewAssembly(AssemblyOptions)` — общая сборка проверки идентичности для сервисов вместо копий в `internal/app`: в `prod` — ServiceAccount Kubernetes (JWKS по HTTPS с CA и отдельным API-токеном, projected-токен для исходящих), в `stage` — короткие JWT с ключами из файлов (`kid` = сервис), в обоих — ключи пользователя через `user.GetSigningKeys` (или локальный провайдер в самом `user`), метрики и одно фоновое задание `Run`; `dev` и неизвестные окружения отклоняются. Значения по умолчанию совпадают с переменными `AUTH_*` assistant. Совместимо: только новые имена; тестовая зависимость `go-grpc v0.1.0` (usage-тест цепочки сервера) поднимает минимальную `prometheus/client_golang` до v1.25.0, как уже у сервисов.

- FIN-311: `NewObservedKeyCache` и интерфейс `KeyObserver`; `Metrics` реализует его и регистрирует gauge `finassist_identity_jwks_skipped_keys{kind=user|service,reason=kty|crv|alg|use|key_ops|size}` — число JWK, пропущенных в текущем снимке. `NewKeyCache` не меняется.

- FIN-243: по решению владельца только пакет internal/pgtest исключён из общего Go-списка инструментирования всех трёх уровней; его тесты продолжают выполняться, выбор пакетов и пустой список проверяются регрессионными тестами.

- FIN-243: независимые unit/integration/consumer API пороги statements 80% с закреплённым go-test-coverage, проверкой непустого исполнения и штатными artifacts вместо изменённых строк; тесты и регламент проверок; тестовые gRPC-обработчики возвращают ошибки вместо FailNow в служебной goroutine.

### Изменено

- FIN-334 (FIN-308, FIN-309): перенесены из go-library-template запреты `forbidigo`/`depguard` FIN-294 — стандартные логгеры (`fmt.Print*`, `slog`/`log` пакета, `grpclog`), глобальный реестр метрик (`prometheus.DefaultRegisterer`/`DefaultGatherer`, `promauto.New*`, `promhttp.Handler`), функции и клиенты пакета `http` по умолчанию, глобальные провайдеры `otel`, `os/signal`, окружение (`os`, `syscall`, `golang.org/x/sys`), функции пакета `flag`, `os.Stdout`/`Stderr`/`Stdin`, `os.TempDir`/`CreateTemp`/`MkdirTemp`, `runtime/debug.Set*`, `runtime.GOMAXPROCS` и смена рабочего каталога; пустой импорт `expvar`, `net/http/pprof`, `golang.org/x/net/trace`, `grpclog/glogger`, `glog`, `klog`, `automaxprocs`, `automemlimit` — с тестом `scripts/test_lint_policy.py` (otel в пробном модуле закреплён вручную, остальные версии — из `go.mod`). Защита CI FIN-301: jobs `lint`, `api`, `migrations` не сохраняют токен checkout, `base_ref` передаётся в скрипт через окружение, тест `scripts/test_workflow_hardening.py`. Формулировки FIN-307 в `docs/releasing.md` и вступлении CHANGELOG: строка в `[Unreleased]` от каждого PR, включая документацию, тесты и CI; заголовок PR выпуска — с ключом FIN; сводка ботских изменений `go.mod` — в PR выпуска. Нарушений новых запретов в коде библиотеки не найдено; runtime и экспортируемый API не менялись.
- FIN-312: записи, вошедшие в уже выпущенный тег v0.1.0, перенесены из «Unreleased» в секцию v0.1.0; в docs/releasing.md записано исключение для GitHub Release v0.1.0. Runtime, API и теги не изменены.

## [v0.1.0] — 2026-10-22

### Добавлено

- FIN-119: проверка JWT пользователя и ServiceAccount, ключи и короткие токены стенда с запретом в prod, кэш JWKS с ротацией и ограничением refresh, таблица вызывающих и контекст, unary/stream интерцепторы, HTTP-middleware, маскирование metadata, метрики отказов и инструкция внедрения; unit-, интеграционные и usage-тесты.
- FIN-119, ревью: общий refresh переживает отмену отдельного запроса; JWKS API-сервера получает отдельный ротируемый токен; допуск 5 секунд для iat/nbf без продления exp; негативные usage-тесты чужого вызывающего/user_id и второго сообщения потока, синхронизированный тест параллельного сбоя JWKS.
- FIN-119, повторное ревью: заблаговременное обновление JWKS с минутными повторами до истечения снимка; кэш коротких JWT стенда учитывает фактический округлённый exp, чтобы не возвращать истёкший токен.
- FIN-119, повторное ревью: проверка необходимости refresh каждые 30 секунд при неизменном минутном ограничителе сетевых загрузок; регрессионный тест задержки тика относительно ограничителя.

### Изменено

- FIN-311: JWK неподдерживаемого типа или назначения (неизвестные `kty`/`crv`/`alg`, `use` не `sig`, `key_ops` без `verify`, RSA длиннее 4096 бит) пропускается, а не отклоняет весь набор JWKS; токен с его `kid` отклоняется как с неизвестным ключом. Набор по-прежнему отклоняется целиком при повреждённых данных, включая JWK без `kty` и повтор `kid` среди пропущенных ключей. Ротация ключа ServiceAccount Kubernetes на EC P-384 или добавление длинного RSA-ключа больше не отключает проверку токенов действующего ключа. Совместимо: прежде принятые наборы принимаются так же.
